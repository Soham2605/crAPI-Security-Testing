 crAPI Security Testing

 📌 Project Overview

This project documents a security assessment and API testing exercise performed on **crAPI (Completely Ridiculous API)**, a deliberately vulnerable application designed for learning and practicing API security testing.

The assessment was performed in a controlled local lab environment to understand common API security vulnerabilities and practice manual security testing techniques.

 🎯 Objectives

* Understand API security testing methodology
* Identify common API vulnerabilities
* Test authentication and authorization mechanisms
* Analyze JWT-based authentication
* Test for Broken Object Level Authorization (BOLA/IDOR)
* Understand API request and response behavior
* Document security findings and observations

 🛠️ Tools Used

* Postman – API request and endpoint testing
* Burp Suite – HTTP request interception and analysis
* JWT.io – JWT token analysis
* Docker – Running the crAPI lab environment
* Web Browser – Application interaction and testing

 🔍 Security Testing Areas

The assessment included testing of:

* API endpoints
* Authentication
* Authorization
* JWT tokens
* BOLA / IDOR
* Input validation
* Access control
* API request manipulation
* Information exposure
* Security misconfigurations

 🧪 Testing Methodology

The testing process generally followed these steps:

1. Set up crAPI in a local lab environment.
2. Identified available application functionality and API endpoints.
3. Captured and analyzed API requests.
4. Tested authentication and authorization controls.
5. Analyzed JWT tokens and authentication-related requests.
6. Manipulated API requests to evaluate access controls.
7. Tested for BOLA/IDOR and other API security issues.
8. Documented observations, evidence, and security findings.
9. Prepared a detailed security assessment report.
